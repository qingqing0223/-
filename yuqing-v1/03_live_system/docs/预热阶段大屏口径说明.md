# 预热阶段大屏口径与模块说明

本文件说明大屏在「民族团结进步宣传周预热阶段」的统计口径、六大模块改动，以及重点账号（creator）数据的预留接口。

## 一、统计口径：只统计预热阶段实际入库的数据

配置文件：`03_live_system/phase.json`

```json
{
  "label": "2026年民族团结进步宣传周预热阶段",
  "stats_start": "2026-09-16T00:00:00",
  "include_history": 0
}
```

- `stats_start`：大屏只统计**该时间点之后入库**（按 `incidents.collected_at`）的数据；
- `include_history = 0`：第一阶段历史基线（`web/assets/data.js` 与库中 `origin='history'` 的 615 条）**保留在库里但不参与展示**，因此不会和之前的舆情混在一起；
- 需要临时放宽时可用环境变量覆盖：

```powershell
$env:LIVE_STATS_START="off"      # 关闭时间过滤
$env:LIVE_INCLUDE_HISTORY="1"    # 把第一阶段历史基线也算进大屏
python .\server.py --no-sim
```

清库可选（默认不需要）：`python .\server.py --reset` 会删库并只按第一阶段数据重建基线，历史基线仍因上面口径而不展示。

## 二、六大模块改动

| 需求 | 落地位置 |
| --- | --- |
| 1. 与历史/测试数据隔离，按今天 0 点起统计 | `phase.json` + `stats.py` 的入库时间过滤 |
| 2. 「非正向态度」改为「重点账号/大V传播监测」 | `web/index.html` 底部第三块面板，展示账号、平台、发帖量、点赞、评论、转发 |
| 3. 右上角各平台单独展示（不再合并） | 固定 9 个平台：小红书、抖音、快手、B站、微博、今日头条、知乎、微信公众号、视频号，数据来自 `bootstrap.platformDetail` |
| 4. 时间趋势按小时 | 默认「按小时」，柱=每小时新增、线=传播热度（点赞+评论+转发的入库合计），数据来自 `bootstrap.trendHourly` |
| 5. 地区改为固定 10 个重点地区 | 五个自治区 + 北京、上海、广州、武汉、哈尔滨，固定顺序展示、不轮播，数据来自 `bootstrap.focusRegions` |
| 6. 实时指标与入库数量对齐 | 累计信息数、最近10分钟新增、当前小时新增、监测地区数、监测平台数、支持认可，全部取自同一批入库记录 |

平台归属规则在 `stats.py` 的 `canonical_platform()`：`哔哩哔哩/B站` → B站，`百度今日头条` → 今日头条，`微信视频号` → 视频号，`微信公众号/公众号` → 微信公众号，其余按名称包含关系归一；未识别的平台归入「其他」并在 `bootstrap.unknownPlatforms` 里列出，便于补规则。

地区归属规则在 `stats.py` 的 `FOCUS_REGIONS`：省/自治区按省级字段匹配；广州/武汉/哈尔滨按城市或地区文本命中。若采集数据只到省级（IP 属地常见情况），广州/武汉/哈尔滨可能为 0，需要采集端补城市字段。

## 三、重点账号（creator）数据接口

大屏已预留展示位和写入接口，采集端（`--main`）的 creator 监测数据接过来后会自动出现在面板里。

写入（与 `/api/ingest` 字段一致，接口会强制标记为重点账号并跳过关键词相关性过滤）：

```powershell
curl -X POST http://127.0.0.1:8765/api/key-accounts/ingest -H "Content-Type: application/json" -d '{
  "records": [
    {
      "platform": "微博",
      "account": "某某账号",
      "text": "民族团结进步宣传周相关内容",
      "region": "新疆",
      "province": "新疆",
      "likes": 5200,
      "comments": 310,
      "shares": 280,
      "collected_at": "2026-09-16T15:30:00",
      "published_at": "2026-09-16T15:00:00",
      "url": "https://example.com/post/1"
    }
  ]
}'
```

读取（面板数据聚合结果）：

```powershell
curl http://127.0.0.1:8765/api/key-accounts
```

聚合口径：按「账号 + 平台」分组，`posts` 为该账号入库帖子数，`likes/comments/shares` 为累计互动量，`heat = likes + comments + shares`，按发帖量→热度排序，最多返回 30 条，大屏显示前 6 条。

另一个等效入口：走标准 `/api/ingest` 时带上 `"是否重点舆情": "是"`（或 `"is_key": 1`），同样会进入重点账号模块。

## 四、自检方法

```powershell
python .\scripts\check_suqi_dashboard.py    # 后端是否在线
curl http://127.0.0.1:8765/api/bootstrap    # 查看 phase / stats / platformDetail / focusRegions / trendHourly / keyAccounts
```

页面每 30 秒自动重新拉取一次数据，`/api/ingest` 写入后也会通过 SSE 立即刷新。
