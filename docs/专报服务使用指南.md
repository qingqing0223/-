### 3. 最小代码

```javascript
const BASE = "https://u784746-8rhl-150771d4.westb.seetacloud.com:8443";
const KEY  = "<你的 API Key>";

// 生成 + 下载（一步到位）
async function downloadReport(cutoff) {
  const res = await fetch(
    `${BASE}/api/v1/report/generate?cutoff=${encodeURIComponent(cutoff)}&download=true`,
    { method: "POST", headers: { "X-API-Key": KEY } }
  );
  if (!res.ok) {
    const err = await res.json();
    alert(err.detail);          // 例如"截止时间早于上一期"
    return;
  }
  const blob = await res.blob();
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = `舆情专报-${cutoff.slice(0, 10)}.docx`;
  a.click();
  URL.revokeObjectURL(url);
}

// 只生成不下载（先给用户看摘要）
async function generateReport(cutoff) {
  const res = await fetch(
    `${BASE}/api/v1/report/generate?cutoff=${encodeURIComponent(cutoff)}`,
    { method: "POST", headers: { "X-API-Key": KEY } }
  );
  return await res.json();
}
```


### 4. 注意
注意1：必须用 POST
注意2：超时要放宽到3分钟
```javascript
axios.post(url, null, {
  timeout: 180000,
  headers: { "X-API-Key": KEY }
})
```
注意3：同一时间连点两次，会**覆盖重出同一期**，期号不变。前端不用做防抖。



### 5. 完整的接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/v1/report/generate?cutoff=...` | 生成，返回 JSON 摘要 |
| `POST` | `/api/v1/report/generate?cutoff=...&download=true` | 生成并返回 docx |
| `GET` | `/api/v1/report/ledger` | 看已出过哪些期 |
| `GET` | `/api/v1/report/health` | 健康检查（判断服务活着没）|


**生成接口的参数：**

| 参数 | 必填 | 说明 |
|---|:---:|---|
| `cutoff` | | 截至时间，`2026-09-22T18:00`。不传取当前时刻 |
| `download` | | `true` 返回文件流；不传返回 JSON |
| `use_llm` | | 是否用大模型写稿；不传按服务端配置 |

**JSON 响应示例：**

```json
{
  "期号": 2,
  "首次出报": false,
  "本期截止": "2026-09-22 18:00",
  "上一期截止": "2026-09-22 14:00",
  "信息总量": 1994,
  "发布内容": 1696,
  "评论及回复": 298,
  "态度分布": { "支持性": 1879, "中性": 103, "问题性": 12 },
  "校验通过": true,
  "文件名": "20260922-第2期-民族团结进步宣传周舆情专报.docx"
}
```

**错误码：**

| 码 | 含义 | 前端怎么办 |
|---:|---|---|
| 200 | 成功 | — |
| 400 | 截止时间早于上一期 | 提示用户选更晚的时间 |
| 401 | API Key 不对 | 检查 Key |
| 422 | 时间格式不对 | 用 `2026-09-22T18:00` 这种格式 |
| 429 | 同时生成的太多 | 提示稍后重试 |
| 500 | 生成失败 | 提示重试，把 detail 发给运维 |

### 7.这套服务是怎么工作的

```
后端 POMS（8000）          ← 采集组写数据、分析组写分类结果
      │ GET 表1-表5、表6-表13
      ↓
专报服务（6006）
      │ ① 统计：平台分布、地区分布、逐小时趋势、TOP10、态度分类
      │ ② 画图：三张图（matplotlib）
      │ ③ 写文字：调大模型 API 生成归纳性内容
      │ ④ 填模板：用 Word 模板+数据生成 docx
      │ ⑤ 校验：数字一致性、占位符残留、图表齐全
      ↓
前端下载 docx
```

**关键设计：数字不经过大模型**

所有统计数字、平台名、表格内容都由程序确定性生成。模型只负责
"归纳性"的那几段文字（比如"问题性内容主要涉及……"），
而且它**拿不到具体数字** —— 从源头上避免编造。

生成完还有一道校验，数字对不上会记进 `outputs/validation.json`。
