# POMS Demo 批量输入输出接口指南

## 1. 批量接口解决什么问题

单条POST适合在 Swagger 中手动测试一条数据。批量POST适合爬虫或算法程序一次提交多条数据。两种接口同时保留，互不影响。

- 单条写入：`POST /api/v1/tables/英文表名`
- 批量写入：`POST /api/v1/tables/英文表名/batch`
- 批量读取：`GET /api/v1/tables/英文表名?page=1&page_size=100`

服务根地址：

```text
http://49.233.133.197:8000
```

## 2. 批量写入JSON格式

批量文件最外层必须是数组 `[]`，数组中的每个 `{}` 是一条完整记录：

```json
[
  {
    "字段1": "第一条数据",
    "字段2": 100
  },
  {
    "字段1": "第二条数据",
    "字段2": 200
  }
]
```

每条记录仍需遵守原表规则：字段不能缺少、增加或乱序；可空字段填 `null`；统计字段没有对应指标时填 `0`。

批量POST需要请求头：

```text
X-API-Key: 后端组提供的API Key
Content-Type: application/json
```

## 3. 批量写入返回格式

成功后返回一个数组，顺序与输入数组一致：

```json
[
  {
    "字段1": "第一条数据",
    "字段2": 100
  },
  {
    "字段1": "第二条数据",
    "字段2": 200
  }
]
```

批量写入是整批事务：任意一条字段校验失败，整批都不会写入。相同主键再次提交时会更新原记录，不会再新增一条重复记录。

## 5. 使用curl批量写入

先设置：

```bash
export POMS_URL='http://49.233.133.197:8000'
export POMS_API_KEY='后端组提供的API Key'
```

以表1为例：

```bash
curl -X POST "$POMS_URL/api/v1/tables/published_content_basic_information/batch" \
  -H "X-API-Key: $POMS_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @01_batch_published_content_basic_information.json
```

`@文件名` 表示把该JSON文件的全部内容作为请求体发送。

## 6. 批量读取并保存一个JSON文件

GET原本就会批量返回JSON数组。例如读取表1前100条并保存：

```bash
curl "$POMS_URL/api/v1/tables/published_content_basic_information?page=1&page_size=100" \
  -o output_table01.json
```

`output_table01.json` 是一个JSON文件，内部数组可以包含多条记录。`page_size` 最大为500；超过500条时，需要修改 `page` 分页下载，或由程序合并。

表6—表9直接GET即可：

```bash
curl "$POMS_URL/api/v1/tables/overall_communication_trend" -o output_table09.json
```

## 7. 推荐调用顺序

采集组批量写入顺序：表1 → 表2 → 表3 → 表4 → 表5。表2依赖表1，表4依赖表1和表2。

分析组先GET表1—表5，算法处理后再批量POST表10—表13。

大屏组和专报组继续使用GET读取，不需要 API Key。

## 8. 常见错误

- 401：API Key缺失或错误。
- 404：关联的发布内容或评论尚未写入。
- 422：数组中至少一条记录字段、顺序、类型或取值不符合要求；整批不会写入。
- 500：联系后端组，并提供操作时间和服务返回内容。
