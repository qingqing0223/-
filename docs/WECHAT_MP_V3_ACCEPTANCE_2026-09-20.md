# 微信公众号 V3 修改与验收报告（2026-09-20）

代码修复、自动测试和真实数据五表导出已完成。**六个关键词的完整真实采集尚未完成**：本轮在第一关键词搜索期间，打开公开文章跳转链接时遇到官方验证码，等待人工处理600秒后停止。未绕过验证码，也未改用非公开接口。当前交付是明确标注 `VERIFY_REQUIRED` 的部分真实结果。

## A. 现有实现审计

1. `wechat/mp_sogou.py` 对整张卡片的全文调用 `parse_public_time(full)`，正文活动日期可以抢先匹配，年回退逻辑导致错误的2025年时间。
2. `wechat/common.py` 的通用 `make_record` 以跳转URL生成ID；搜狗链接中的query/token导致跨关键词ID不稳定。旧去重还会直接丢掉第二个命中关键词。
3. 旧帐号选择器漏掉真实页面的 `.s-p .all-time-y2`。
4. `run_wechat_platform.py` 将公众号记录交给旧分类/标准化管线，不符合采集组仅负责表1—表5的要求，也存在未知互动量被填零的风险。
5. 旧入口没有公众号专用的主题判断、五表导出和独立输出周期；旧启动脚本要求DashScope，升级脚本会操作Git并可启动自动同步。

基线在修改前以仓库原有unittest运行：109项通过。本机初始没有默认python命令，也没有pytest/Playwright；已在仓库被忽略的`.venv`中安装运行及测试依赖。

## B. 最小修改与影响范围

保留原搜狗有头Playwright采集方式，修补卡片解析和分页；增加公众号专用记录处理、持久化和导出模块。`run_wechat_platform.py` 仅对 `wechat_mp` 提前分流，旧分类与推送导入移到视频号分支后。`wechat/common.py`、公共标准化/分类模块和其他平台采集器均未修改。

共享PowerShell脚本只增加显式公众号分支。`setup_wechat_windows.ps1` 不带平台参数时保留原有安装行为；公众号独立安装使用 `-Platform wechat_mp`。视频号运行逻辑保留。

## C. 四个Bug的修复

| Bug | 实现与证据 |
|---|---|
| 发布时间 | 只读来源区 `.s-p .s2` 等专用时间元素，优先读取该区域公开的 `timeConvert(epoch)`。日期文本使用完整匹配，不能解析整段文章；无法可靠判断时留空并排除正式表。测试覆盖用户提供的“正文9月21日、卡片3小时前、采集9月16日”案例。 |
| 跨关键词去重 | 优先canonical公众号URL，剔除追踪参数；无法解析时回退到规范化标题+帐号，可靠绝对日期用于区分重发。相对时间、搜索关键词、临时token不参与ID。持久化合并全部`matched_keywords`，保留首次ID/采集时间，另记最后观察时间。已知不同canonical URL或不同绝对日期不合并。 |
| author为空 | 实际公开DOM确认帐号名称在 `.s-p .all-time-y2`；新增该选择器。真实采集37条记录的帐号名称均非空。脱敏来源区HTML在被忽略的`data/wechat_mp/debug`中。 |
| 未知指标为0 | 新公众号链绕开旧标准化与模型管线，缺失互动量使用None，CSV空字段、XLSX真正空单元格。测试同时验证真实0可以保留，未知值不会覆盖已有可靠0。 |

没有态度分类，也不调用DashScope/Qwen。主题有效性仅依据公开标题/摘要、可靠发布时间及本次活动上下文。关键词命中本身不是有效性证据。重点帐号名单独立配置，Unicode/空白规范化后精确匹配，未匹配不猜帐号类型。
